# 📅 Enterprise Leave Management System (ระบบบริหารจัดการการลา)

ระบบบริหารจัดการการลาของพนักงานในองค์กรแบบสแตติก พัฒนาขึ้นด้วยเทคโนโลยีเว็บสมัยใหม่เพื่อตอบสนองการคำนวณวันลา โควตาการลาตามกฎหมายแรงงานไทย การอนุมัติคำขอลา และรองรับการทำงานบนเบราว์เซอร์ได้ทันทีโดยไม่ต้องใช้ Backend Server ซับซ้อน

🌐 **Live Production URL:** https://pichsinee2003-bit.github.io/leave_managemet_system/

---

## 📌 บทสรุปภาพรวมโครงการ (Executive Summary)

โครงการนี้พัฒนาขึ้นเพื่อเพิ่มประสิทธิภาพและขยายขอบเขตการทำงานของระบบบริหารจัดการภายในองค์กร ให้ครอบคลุมมิติของการลาและการจัดการวันหยุด โดยแบ่งการทำงานออกเป็น 2 มุมมองหลัก:

1. **HR / Admin Management Portal:** แผงควบคุมสำหรับผู้บริหารและฝ่ายบุคคล ตรวจสอบ อนุมัติ/ปฏิเสธคำขอลา และบริหารจัดการคำขอของพนักงาน
2. **Employee Self-Service Portal:** หน้าต่างบริการตนเองของพนักงาน ตรวจสอบโควตาวันลาคงเหลือ ยื่นคำขอลาออนไลน์ และตรวจสอบสถานะคำขอลาของตนเองแบบเรียลไทม์

---

## 🛠️ เทคโนโลยีและสถาปัตยกรรม (Tech Stack & Architecture)

### 1. Frontend
* **HTML5:** โครงสร้างหลักของหน้าเว็บ (Semantic Web) เช่น ฟอร์มขอลา ปุ่มกด และตารางข้อมูล
* **CSS3:** ตกแต่งเลย์เอาต์ สีสัน ตัวอักษร และการจัดหน้าจอ
* **Modern JavaScript (Vanilla JS):** ควบคุมการทำงานแบบไดนามิก (Interactive) เช่น การคำนวณวันลาอัตโนมัติ, เปิด-ปิด Modal และ Form Validation

### 2. Styling (Tailwind CSS)
* **ผ่าน CDN:** โหลดใช้งานผ่านคลาวด์โดยไม่ต้องติดตั้ง Build Tools เพิ่มเติม
* **Modern Design:** ดีไซน์สวยงาม ทันสมัย มีเงาและขอบมนเป็นมาตรฐานสากล
* **Responsive Design:** รองรับการแสดงผลทุกหน้าจอ (มือถือ, แท็บเล็ต, คอมพิวเตอร์)

### 3. UI Components
* **Modern Card:** กล่องข้อมูลสี่เหลี่ยมขอบมนสำหรับแบ่งหมวดหมู่ เช่น สรุปวันลาคงเหลือหรือสถานะคำขอลา
* **Modal Design:** หน้าต่างป๊อปอัปสำหรับกรอกฟอร์มหรืออนุมัติงาน ช่วยให้ผู้ใช้โฟกัสกับงานตรงหน้าโดยไม่ต้องเปลี่ยนหน้าเว็บ
* **Interactive Dashboard:** หน้าจอรวมสถิติ ข้อมูลสรุป และปุ่มลัดเพื่อจัดการระบบได้ทันที

### 4. Backend & Database Simulation
* **ไม่มี Backend:** ไม่มีเซิร์ฟเวอร์ส่วนกลาง (เช่น Node.js, PHP)
* **ไม่มี Database จริง:** ไม่มีฐานข้อมูล (เช่น MySQL, MongoDB)
* **Static Website 100%:** ทำงานด้วยไฟล์ HTML, CSS, JS ล้วน สามารถเปิดใช้งานผ่านเบราว์เซอร์หรือDeploy บน Static Hosting (เช่น GitHub Pages, Vercel) ได้ทันที

### 5. Data Storage (LocalStorage)
* **Browser localStorage:** ใช้พื้นที่จัดเก็บข้อมูลในตัวเบราว์เซอร์ของผู้ใช้
* **การจำลองฐานข้อมูล:** ข้อมูลพนักงานและสถานะคำขอลาจะถูกแปลงเป็น JSON และบันทึกไว้ ทำให้ข้อมูลไม่หายไปเมื่อรีเฟรชหน้าเว็บ (ข้อมูลจะบันทึกเฉพาะในเครื่องของผู้ใช้งานแต่ละคน)

# LeaveFlow Pro - ระบบจัดการลางานออนไลน์

**LeaveFlow Pro** เป็นเว็บแอปพลิเคชันสำหรับบริหารจัดการและยื่นคำขอลางานภายในองค์กร รองรับการทำงานทั้งฝั่งพนักงานทั่วไป (ผ่านรหัสพนักงาน) และฝั่งผู้บริหาร (ผ่านรหัส PIN)

---

## 🗄️ โครงสร้างการจัดเก็บข้อมูล (Data Architecture & Simulation)

เนื่องจากระบบถูกออกแบบมาให้เป็น **Static Website (HTML/JS)** ที่รันบน GitHub Pages จึงใช้งาน **`localStorage`** ในการจำลองฐานข้อมูลเสมือนจริง (In-browser Database) ซึ่งประกอบด้วยโครงสร้างข้อมูลหลัก 3 ส่วน ดังนี้:

### 1. ข้อมูลพนักงาน (`employees`)
จัดเก็บรายละเอียดและโควตาวันลาคงเหลือรายปีของพนักงาน
* `id`: รหัสพนักงาน (เช่น `EMP01`, `EMP02`)
* `name`: ชื่อ - นามสกุลพนักงาน
* `position`: ตำแหน่งงาน
* `dept`: แผนกหรือฝ่าย
* `sick_remain`: จำนวนวันลาป่วยคงเหลือ (ค่าเริ่มต้น 30 วัน)
* `personal_remain`: จำนวนวันลากิจคงเหลือ (ค่าเริ่มต้น 6 วัน)
* `vacation_remain`: จำนวนวันลาพักผ่อนคงเหลือ (ค่าเริ่มต้น 10 วัน)
* `pin_code`: รหัส PIN สำหรับยืนยันตัวตนก่อนเข้าสู่ระบบของพนักงาน

### 2. ข้อมูลผู้บริหาร / แอดมิน (`admins`)
จัดเก็บรายชื่อคณะผู้บริหารที่มีสิทธิ์อนุมัติและจัดการระบบ
* `name`: ชื่อ - นามสกุลผู้บริหาร (เช่น *คุณพิชญ์สินี ทับพยุง*, *คุณณัฐพงศ์ พรมสงฆ์*)
* `pin_code`: รหัส PIN สำหรับยืนยันตัวตนก่อนเข้าสู่ระบบจัดการ

### 3. รายการคำขอลางาน (`leave_requests`)
เก็บบันทึกประวัติการยื่นใบลาทั้งหมด พร้อมสถานะและผู้ตรวจสอบ
* `id`: รหัสคำขอลา (Timestamp)
* `emp_id`: รหัสพนักงานผู้ยื่นลา
* `emp_name`: ชื่อพนักงานผู้ยื่นลา
* `leave_type`: ประเภทการลา (ลาป่วย, ลากิจ, ลาพักผ่อน)
* `start_date`: วันที่เริ่มต้นลา
* `end_date`: วันที่สิ้นสุดลา
* `days`: จำนวนวันลาสุทธิ (คำนวณอัตโนมัติ)
* `reason`: เหตุผลความจำเป็นในการลา
* `status`: สถานะคำขอปัจจุบัน (`รออนุมัติ`, `อนุมัติ`, `ไม่อนุมัติ`)
* `approver_name`: ชื่อผู้บริหารที่ทำการกดอนุมัติหรือปฏิเสธ

## ⚙️ ตรรกะการทำงานของระบบ (Business Logic)

1. **ระบบยืนยันตัวตน (Dual Login System):**
   * **พนักงาน:** เข้าสู่ระบบด้วยรหัสพนักงาน (เช่น `EMP01`) เพื่อตรวจสอบโควตาและยื่นใบลา
   * **ผู้บริหาร (Admin):** เลือกชื่อผู้บริหารและกรอกรหัส PIN เพื่อเข้าสู่หน้าจออนุมัติคำขอ
2. **การคำนวณวันลาอัตโนมัติ:** ระบบคำนวณระยะเวลาระหว่างวันที่เริ่มต้นและวันที่สิ้นสุดเป็นจำนวนวันลาสุทธิทันทีเมื่อส่งฟอร์ม
3. **การจัดการสถานะแบบเรียลไทม์:** ข้อมูลการยื่นลาและการอนุมัติจะถูกบันทึกและอัปเดตผ่าน `localStorage` ทำให้จำลองกระบวนการทำงานจริงได้อย่างราบรื่นบนเว็บเบราว์เซอร์
